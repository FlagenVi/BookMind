# Интеллектуальная веб-платформа для формирования сжатого изложения текстов

Продуктовое направление проекта — веб-читалка, которая сохраняет прогресс и помогает восстановить контекст только уже прочитанной части книги без спойлеров. Основной сценарий, ограничения и этапы разработки зафиксированы в [PRODUCT_VISION.md](PRODUCT_VISION.md). Отдельный рабочий список задач по читалке и инфраструктуре без AI находится в [docs/TASKS_WITHOUT_AI.md](docs/TASKS_WITHOUT_AI.md).

Проектирование читалки и надёжной загрузки EPUB/FB2/TXT/PDF: [READER_ARCHITECTURE.md](docs/READER_ARCHITECTURE.md).

Работают регистрация, вход, профиль и личные документы. Backend: Java 21, Spring Boot 4, Spring Security, Spring Data JPA, PostgreSQL и Flyway. Frontend: React + TypeScript + Vite + Tailwind. Node.js нужен только для инструментов frontend.

## Запуск frontend

Требуется Node.js 22.12+ (проверено на 22.20.0) и npm.

```powershell
cd frontend/ProjectF
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite (обычно http://127.0.0.1:5173).

## Backend

Подготовка новой PostgreSQL, переменные подключения и переход существующей БД описаны в [DATABASE.md](backend/ProjectF/DATABASE.md). После настройки `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, при наличии JDK 21:

```powershell
cd backend/ProjectF
.\gradlew.bat bootRun --args='--spring.profiles.active=postgres'
```

Профиль `postgres` включает Flyway и проверку схемы Hibernate. Существующая рабочая БД не изменялась; значения секретов не читались. Миграции проверяются на отдельном PostgreSQL через Testcontainers.

Для точного постраничного просмотра DOCX backend создаёт и сохраняет PDF-копию. В Windows сначала используется установленный Microsoft Word, поэтому разметка совпадает с Word максимально точно; стандартная установка обнаруживается автоматически, а нестандартный путь задаётся через `WORD_PATH`. На сервере без Word используется LibreOffice в headless-режиме (`SOFFICE_PATH`). Если оба конвертера отсутствуют, frontend включает совместимый HTML-просмотр DOCX и показывает соответствующее сообщение.

Frontend отправляет запросы на `/api`; dev-прокси в `frontend/ProjectF/vite.config.ts` направляет их на `http://localhost:8080`. Если backend использует другой порт, измените `target`. Переменные окружения фронтенду на этом этапе не нужны. Для production нужен reverse proxy `/api` к backend и возврат `index.html` для клиентских маршрутов.

## Реализовано

- React + TypeScript (strict) + Vite + Tailwind CSS через официальный Vite-плагин.
- React Router, TanStack Query, Fetch API, React Hook Form + Zod, Lucide.
- Базовый компонент Button на Radix Slot / CVA, совместимый с подходом shadcn/ui; полный набор shadcn/ui пока не добавлен.
- Русский адаптивный интерфейс, ввод текста, валидация, серверная загрузка TXT UTF-8 (до 10 МБ / 5 000 000 символов); ручной ввод — до 100 000 символов.
- Регистрация и вход через серверную сессию в HttpOnly-cookie, хеширование паролей PBKDF2, защита CSRF, выход с завершением сессии.
- Сохранение, список с пагинацией, просмотр и удаление личных документов через `/api/documents`. Владелец определяется по сессии на сервере.
- Состояния загрузки, ошибки сервера, пустая история, повтор запроса.
- Страницы `/`, `/history`, `/history/:id`, `/auth`, `/profile`, страница 404. Рабочие страницы требуют входа, профиль показывает email, дату регистрации и число документов.
- Первая версия библиотеки `/library` и читалки `/library/:id/read`: оглавление по подготовленным разделам, прокрутка, одна страница, разворот, белая/сепия/тёмная тема, размер и семейство шрифта, интервал и ширина текста.
- Серверное сохранение позиции чтения, закладок, выделений и заметок. Позиции задаются смещениями в исходном тексте и не зависят от визуальной пагинации.
- Исходные байты загруженных файлов сохраняются в PostgreSQL вместе с SHA-256 и размером. Клиент передаёт файл блоками по 4 МБ и в рамках открытой страницы продолжает с подтверждённого сервером смещения после сбоя. Завершение сверяет размер и SHA-256. Допустимый файл принимается полностью до 30 МБ; превышение лимитов или слишком большой извлечённый текст отклоняются без молчаливого усечения.
- PDF открывается через PDF.js как исходные белые страницы со всеми изображениями. DOCX конвертируется LibreOffice в сохранённую PDF-копию и открывается тем же постраничным просмотрщиком; Apache PDFBox и Apache POI параллельно извлекают текст и структуру для поиска, заметок и AI.

Новый API использует `users` и `documents`. Чужой документ возвращает 404 при чтении или удалении. Старая таблица `note` сохранена, но `/api/notes` закрыт: записи без владельца не должны становиться доступны новым пользователям. Подключена поэтапная суммаризация через DeepSeek с сохранением промежуточных ответов. Контракты и особенности сессий: [AUTH_API.md](backend/ProjectF/AUTH_API.md).

## Проверки backend

При запущенном Docker: `cd backend/ProjectF`, затем `.\gradlew.bat test`. Интеграционные тесты на временном PostgreSQL проверяют миграции, длинные тексты, регистрацию/вход/выход, CSRF и его обновление, смену ID сессии, изоляцию пользователей и удаление документов. Рабочая БД и её секреты для тестов не нужны.

## Проверки frontend

```powershell
cd frontend/ProjectF
npm run build
npm run lint
npm run format:check
```

## Структура

- `backend/ProjectF` — существующий Java backend.
- `frontend/ProjectF/src/pages` — редактор, список и просмотр текстов.
- `frontend/ProjectF/src/api` — типизированные запросы.
- `frontend/ProjectF/src/components/ui` — общие компоненты.
- `frontend/ProjectF/src/App.tsx` — маршруты, навигация, провайдер Query.
- `PROMPT.md` — исходный контекст; упоминания NestJS/Node.js как backend заменены решением использовать Java.

## Большие документы
